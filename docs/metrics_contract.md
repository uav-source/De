# Metrics Contract

This file freezes Day 1-14 metrics. Every metric must be computed by script and
stored in CSV or manifest output.

## Inputs

The evaluator expects:

- `gt.tum`: ground-truth trajectory.
- `pose_est_toy.tum`: estimated trajectory from the minimum probe.
- `axis.csv`: unit axis per frame or local centerline tangent.
- ODI CSV: framewise `ODI`, `AIS`, `lambda_min`, `condition_number`,
  eigenvalues, weak direction, and reliability flags.

Ground truth may be used for final evaluation and synthetic motion generation.
It must not be used to directly correct an estimated pose.

## ATE

Absolute trajectory error is computed after SE(3) alignment when needed:

```text
e_pos(t) = p_est_aligned(t) - p_gt(t)
ATE_RMSE = sqrt(mean(||e_pos(t)||_2^2))
```

Because LiDAR-Inertial odometry has metric scale, Sim(3) scale fitting is not
allowed for Day 1-14 reporting.

## RPE

Relative pose error uses a fixed frame or distance window:

```text
T_rel_gt = inv(T_gt(t)) T_gt(t + k)
T_rel_est = inv(T_est(t)) T_est(t + k)
E_rel = inv(T_rel_gt) T_rel_est
```

The Day 1-14 implementation may start with translational RPE, but the report
must state the chosen window.

## Axis Error

For a unit tunnel axis or local tangent `a(t)`:

```text
e_axis(t) = |a(t)^T (p_est(t) - p_gt(t))|
```

Axis error is the primary direction-specific error for straight and curved
tunnel-like scenes.

## Cross Error

```text
e_cross(t) = ||(I - a(t)a(t)^T)(p_est(t) - p_gt(t))||_2
```

Cross error checks whether any improvement or failure is direction-specific
instead of only changing average ATE.

## Weak-Direction Drift Rate

Let `v_p(t)` be the normalized translation component of the reliable weak
direction. The weak-direction projection error is:

```text
e_weak(t) = |v_p(t)^T (p_est(t) - p_gt(t))|
```

The drift rate is computed over sliding windows:

```text
weak_drift_rate = error_increase / path_length
```

or by a linear slope fit. The implementation must record which option is used.

Frames with unreliable weak direction are excluded from weak-drift correlation,
but their exclusion count must be reported.

## Axis Alignment

```text
axis_alignment(t) = |v_p(t)^T a(t)|
```

Straight tunnel Day 14 gate:

```text
median(axis_alignment) >= 0.70
```

Only reliable weak-direction frames count toward this median.

## Drift Alignment

Let a window drift vector be:

```text
d(t0,t1) = normalize((p_est(t1)-p_gt(t1)) - (p_est(t0)-p_gt(t0)))
```

Then:

```text
drift_alignment = |v_p^T d|
```

This is used to check whether weak direction aligns with observed maximum drift,
not only with the known tunnel axis.

## ODI Correlation

Window-level samples are generated by pairing:

- mean or median ODI in a window,
- axis drift rate in that window,
- weak-direction drift rate in that window when reliable,
- optional high-error flag.

The Day 14 minimum correlation check is:

```text
Spearman(ODI, axis_drift_rate) >= 0.50
```

This is only an initial probe threshold, not a publication claim.

## Alternative Metric Comparison

The same correlation and optional AUC pipeline must compare:

- ODI
- condition_number
- lambda_min
- AIS

Day 14 requires ODI to outperform at least one of `condition_number` or
`lambda_min` on the selected drift target. If not, the report must diagnose
whether the issue is scene geometry, Jacobian, whitening, epsilon, toy_lio, or
the ODI definition itself.

## Warning Features

Day 1-14 does not make a formal risk-warning claim. The pipeline may record
risk features for later use, but no Day 14 decision may rely on warning AUC
unless the data and labels are explicitly generated by script.
