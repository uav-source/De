# Zero-Perturbation PCL Backend Qualification v2

Status: prospectively frozen before the v2 CLI diagnostic implementation and
before executing any v2 microtest. This protocol evaluates only whether the
frozen PCL implementation is technically valid enough to enter a future Phase
A qualification. It does not execute or pass Phase A, Phase B, Development, or
Confirmatory work.

## v1 is preserved and reclassified, not rewritten

The v1 result at commit `04cb2e36c2af75500ae1b5c65bd7c2b037613bfe`
remains immutable:

- `PCL_DEPENDENCY_READY = true`
- `PCL_CLI_COMPILED = true`
- `PCL_V1_PLANAR_IDENTITY_SMOKE = FAIL`

The original 64-point source and target fixtures remain byte-for-byte
unchanged. All points have `z=0`, coordinate covariance rank 2, and identical
source/target coordinates. With a point-to-plane residual and planar normals,
the six-column rigid-body Jacobian spans only the two rotations that tilt the
plane and translation normal to the plane. Its Hessian rank is 3, with sorted
eigenvalues `[0, 0, 0, 3.36, 3.36, 64]`. Translation within the plane and
rotation about the plane normal are unobservable.

Therefore v1 remains a failed smoke execution but is not a valid six-degree-of-
freedom backend qualification gate. v2 records:

- `PCL_V1_SMOKE_FIXTURE_DEGENERATE = true`
- `PCL_BACKEND_QUALIFICATION = NOT_EVALUATED`

This is a scope correction, not a retrospective PASS.

## Frozen implementation and firewalls

PCL remains version 1.15.1. Both clouds use one-thread
`NormalEstimationOMP`, KSearch=50. Registration remains
`IterativeClosestPointWithNormals` with explicit
`TransformationEstimationPointToPlaneLLS`, 0.50 m maximum correspondence
distance, 50 iterations, transformation epsilon `1e-10`, fitness epsilon
`1e-10`, reciprocal correspondences off, symmetric objective off, and
same-direction normals on. No result may change these values.

The v2 generator contains no RNG and reads no seed schedule. Development,
Confirmatory, and old Test seeds are forbidden. Open3D and Native are neither
invoked nor modified. A failed microtest stops this route; no third backend or
parameter rescue is permitted.

## Locked nondegenerate fixture

`tests/data/pcl_backend_v2/generate_fixtures.py` deterministically constructs
806 finite unique XYZ points from three mutually perpendicular planes plus the
five exposed faces of an off-centre cuboid bump. Identity source and target
files are byte-identical. The coordinate covariance rank is 3. Analytic
surface normals span three dimensions, and the analytic point-to-plane Hessian
has rank 6 with sorted eigenvalues:

```text
126.96221040873503
131.15107985614438
136.67100767861896
230.31747283225394
289.94028524243305
328.8629856151476
```

The generator, every generated PCD/config/truth file, fixture manifest, and the
unchanged v1 PCD inputs are SHA-256 locked in the YAML protocol and fixture
`SHA256SUMS`. Regeneration must reproduce those hashes before execution.

## Exactly three microtests

### A. NONDEGENERATE_IDENTITY

The nondegenerate source and target coordinates are identical, and the initial
transform is identity. The structured verifier independently requires raw PCL
convergence, finite transform and fitness, translation and rotation updates no
greater than `1e-8`, at least one final correspondence, and zero NaN or zero
normals in both clouds.

### B. KNOWN_SMALL_TRANSFORM

The target is the same nondegenerate cloud. The source is generated by applying
translation `[0.01, -0.02, 0.03]` m and RPY `[0.2, -0.3, 0.5]` degrees using
`Rz(yaw) @ Ry(pitch) @ Rx(roll)`. PCL receives identity initialization but does
not receive truth. The independent verifier compares the estimated source-to-
target transform with the inverse applied transform and requires translation
and geodesic rotation errors no greater than `1e-4`, plus raw convergence and
finite transform/fitness.

### C. PLANAR_DEGENERACY_DIAGNOSTIC

The unchanged v1 PCDs are processed as a diagnostic. The verifier requires
coordinate rank 2, point-to-plane Jacobian rank below 6, and
`rank_deficient=true`. Raw `hasConverged()` is recorded but is not a gate. A
failure of these diagnostic expectations is itself a mandatory v2 failure and
cannot be ignored.

CTest invokes one Python verifier per test. Each verifier parses one JSON
document and evaluates fields independently; no multi-field output regex is
used.

## Diagnostic separation and decision rule

The CLI separately exposes raw convergence, transform finiteness, fitness
finiteness, composite finite output, implementation qualification status,
iterations, final correspondences, source/target normal statistics, coordinate
rank, and point-to-plane Hessian rank/eigenvalues. A primary failure reason is
chosen from the frozen vocabulary in the YAML; the v1 combined failure string
is not emitted by v2.

`PCL_BACKEND_IMPLEMENTATION_VALID` and
`PCL_BACKEND_PHASE_A_QUALIFICATION_AUTHORIZED` are true only when Test A and B
pass and Test C's diagnostic expectation also passes. This authorizes only a
future, separately controlled Phase A execution. v2 itself runs no Phase A or
Phase B trial.
