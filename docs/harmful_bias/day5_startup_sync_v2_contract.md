# Day 5 Startup-Sync Remediation V2 Contract

## Scope

This work is an engineering runtime repeatability check, not Day 6 and not a scientific evaluation. It may repair only the Git-aware source lock, the expected FAST-LIO2 runtime-output allowlist, the same-process monotonic unpause timing, and the AUDIT_ONLY startup-sync runner. It reuses the two frozen read-only replay clips and the existing FAST-LIO2 binary. It must not rebuild or modify FAST-LIO2, run tap OFF/ON equivalence, call the detector, calculate ODI, or run Development, Holdout-Dev, or Future Test.

The only real-data purpose is `ENGINEERING_RUNTIME_REPEATABILITY_CHECK`. The run ID is `multihyp_day5_startup_sync_v2`, with Quick Shack R1/R2/R3 followed by Outdoor R1/R2/R3, all in `AUDIT_ONLY` with tap, observation export, and detector disabled. A failed pre/post lock, clip, binary, allowlist, handshake, or replay check consumes the run ID and stops the remaining matrix.

## Source and runtime-output identity

For each Git repository, the source set is generated by `git ls-files --cached --others --exclude-standard -z`, sorted by UTF-8 path bytes, and records path, tracked status, file type, mode, size, SHA-256, and non-followed symlink target. The identity also records branch, commit, binary Git diff SHA-256, porcelain status, nonignored untracked paths, submodule commits, CMakeLists/package hashes, and the existing binary identity. Git configuration and remote URLs are excluded.

The only FAST-LIO2 runtime paths allowed to be cleared or changed are:

- `Log/mat_pre.txt`
- `Log/mat_out.txt`
- `Log/dbg.txt`
- `Log/pos_log.txt`
- `Log/fast_lio_time_log.csv`
- `PCD/scans.pcd`

These paths are excluded by Git ignore rules and are not source. Any changed file under `Log/` or `PCD/` outside this list fails immediately. In particular, a change to `Log/mat_pre.txt` is expected runtime output and cannot fail the source lock.

## Startup synchronization

Each run uses an isolated ROS master, ROS home, and ROS log directory. FAST-LIO2 starts before a paused `/day5_bag_player`. The graph and both nodes' TCPROS bus views must show exactly one publisher and subscriber for `/livox/lidar` and `/livox/imu`, with all four directions connected, for 20 continuous polls at 0.1 seconds. The same Python handshake process then calls `/day5_bag_player/pause_playback` (`std_srvs/SetBool`, `data: false`) and records:

- `handshake_start_monotonic_ns`
- `handshake_ready_monotonic_ns`
- `unpause_call_start_monotonic_ns`
- `unpause_call_end_monotonic_ns`
- `unpause_wall_time_utc`

The four monotonic values must be nondecreasing. The runner cannot call the service a second time and cannot use a shell wall clock as monotonic time.

## Comparison and Gate semantics

Each sequence is compared R1/R2, R1/R3, and R2/R3 by `scan_index` with no index or timestamp search. Scan membership and exact timestamps, MeasureGroup, prior state/covariance, formal Jacobian/residual, accepted indices, correspondences, posterior state/covariance, map size, and final-map checksums must match. Maximum position, rotation, and covariance differences remain bounded by `1e-12`; comparator mathematics and tolerances are unchanged.

Full-matrix statuses are `PASS`, `FAIL`, or `NOT_EVALUATED`. They can become PASS or FAIL only after 6/6 successful replays and all six pair comparisons. Executed-run counts remain separate, so one successful replay cannot produce a full-matrix PASS.
